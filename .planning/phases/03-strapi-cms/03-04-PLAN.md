<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Strapi → Next (`POST /api/revalidate`) | Entrada não autenticada vinda da rede; qualquer um na rede pode chamar |
| Strapi → Next (payload de conteúdo) | JSON do CMS atravessa para virar props; pode conter `__component` fora do contrato |
| Servidor Next → navegador (`.next/static`) | Fronteira de vazamento: tudo que cruza é público |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | `POST /api/revalidate` | mitigate | Task 1 prova 401 sem header, com header errado e com ambiente sem `REVALIDATE_SECRET`, e prova que `revalidateTag` não é chamado em nenhum dos três |
| T-03-02 | Tampering | Dynamic Zone `blocos` | mitigate | Task 2 prova que `__component` desconhecido e bloco conhecido inválido viram `null` via `blocoTolerante`, sem derrubar `paginaSchema` |
| T-03-03 | Information Disclosure | `.next/static` | mitigate | Task 3 cria `scripts/verifica-segredo-no-bundle.mjs`, roda o build com sentinelas nos envs de servidor e falha se qualquer sentinela ou nome de segredo aparecer no bundle |
| T-03-04 | Denial of Service | `POST /api/revalidate` sem rate limit | accept | Rota só revalida tags de um mapa fechado de 8 modelos, operação idempotente e barata; rate limiting é entrega declarada da Fase 15 |
| T-03-05 | Repudiation | Deriva silenciosa entre modelo do Strapi e schemas do Next | mitigate | Task 1 (paridade de tags `cms:*`) e Task 2 (paridade dos 13 blocos) quebram o CI assim que um lado mudar sem o outro |
| T-03-SC | Tampering | Instalações npm | mitigate | Nenhum pacote novo é instalado neste plano — os três arquivos usam apenas `node:fs`, `node:path`, `jest` e `zod` já presentes. Se surgir necessidade de instalar, parar e abrir checkpoint humano bloqueante antes do install |
</threat_model>

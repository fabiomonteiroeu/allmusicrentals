Criar `src/components/blocos/renderizador.tsx` — **Server Component** (sem `'use client'`).

Assinatura: `export function RenderizadorDeBlocos(props)`, onde `props` é um objeto com cinco chaves —
`blocos: Bloco[]`, `locale: Locale`, `categorias: Categoria[]`, `produtosDestaque: Produto[]` e
`avaliacoes: Avaliacao[]`. Os três últimos são os dados próprios dos Blocos 3, 4 e 8, que o componente do CMS não
carrega.

Importar `type { Bloco, Categoria, Produto, Avaliacao }` de `@/lib/cms/adapters` — **nunca** de
`@/lib/cms/schemas.ts`, que expõe o formato cru pré-adaptação.

Corpo: `blocos.map((bloco, i) => { switch (bloco.__component) { ... } })` envolvido em `<>...</>`.

**`switch`, não `Record<string, FC>`.** Razão a comentar no arquivo: `tsconfig.json` tem
`noUncheckedIndexedAccess: true`, então `mapa[bloco.__component]` seria tipado `FC | undefined` em toda chamada,
forçando um `if` de runtime redundante e perdendo o narrowing das props. O `switch` sobre a união discriminada
preserva o tipo estreitado em cada `case`. É a mesma técnica de `adaptarBloco` em `src/lib/cms/adapters.ts`.

Os 9 `case`, com `key={bloco.id ?? i}` em cada um:
| `__component` | Chamada |
|---|---|
| `'blocos.hero'` | `<HeroBloco bloco={bloco} locale={locale} />` |
| `'blocos.busca'` | `<BuscaBloco bloco={bloco} locale={locale} />` |
| `'blocos.grade-de-categorias'` | `<GradeDeCategoriasBloco bloco={bloco} locale={locale} categorias={categorias} />` |
| `'blocos.produtos-em-destaque'` | `<ProdutosEmDestaqueBloco bloco={bloco} locale={locale} produtos={produtosDestaque} />` |
| `'blocos.destaque-led'` | `<DestaqueLedBloco bloco={bloco} locale={locale} />` |
| `'blocos.como-funciona'` | `<ComoFuncionaBloco bloco={bloco} />` |
| `'blocos.diferenciais'` | `<DiferenciaisBloco bloco={bloco} />` |
| `'blocos.avaliacoes'` | `<AvaliacoesBloco bloco={bloco} locale={locale} avaliacoes={avaliacoes} />` |
| `'blocos.chamada-final'` | `<ChamadaFinalBloco bloco={bloco} locale={locale} />` |

`default: return null;` — bloco desconhecido (ou de outra página, como `blocos.texto-rico`/`blocos.faq`/
`blocos.formulario-contato`/`blocos.comparativo-led`, reservados às Fases 6 e 11) **nunca quebra a página**. Mesma
garantia que `blocoTolerante`/`adaptarBlocos` já dão no nível de dados. Comentar isso.

**Não** usar spread `{...bloco}` em nenhum `case`, e **não** chamar `sanitizarRichText` — o rich text já chega como
`HtmlSeguro` do adaptador, e nenhum dos 9 blocos da Home tem campo de rich text.
